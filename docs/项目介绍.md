# 成步堂的选择 · 项目介绍文档

---

## 一、项目概览（一句话说清）

- **项目名称：** 成步堂的选择（Ace Attorney MVP）
- **介绍：** 一款以《逆转裁判》为灵感、由大语言模型驱动的 Web 推理庭审游戏——玩家扮演辩护律师成步堂，在 AI 助手真宵的协助下调查取证、交叉询问证人，并在庭审中用「异议 + 证物 + 逻辑还原」争取无罪判决。

---

## 二、为什么做（Why）

### 1. 受众是谁？

**核心受众：** 18–35 岁，熟悉或喜爱推理、视觉小说、JRPG 的轻度/中度玩家；也包括对 AI 互动叙事好奇的创作者与开发者。

**身份与偏好：**

- 玩过或了解《逆转裁判》《弹丸论破》等「找矛盾—出示证物—当庭反驳」类作品
- 习惯在 PC/浏览器碎片化游玩（单局 15–30 分钟）
- 对「角色有性格、对话不千篇一律」有期待，愿意与 AI 助手协作推理

**遇见情境：**

- 课后/通勤后想玩一局「动脑又带感」的推理小游戏
- 在 AI 创作、Game Jam、课程/竞赛展示中体验「LLM + 游戏机制」的可能性
- 作为粉丝向 Demo，重温法庭辩论的紧张感与「异议！」的爽感

---

### 2. 你想为他们创造什么？

我们想传递的核心体验是：**「像成步堂一样思考，像真宵一样被陪伴」**——推理不只是选对选项，而是自己组织语言、指出矛盾，并在失败时被角色「拉回来」继续试。

**故事 / 观察 1：**  
很多 AI 文字冒险「聊什么都能过」，缺少胜负与节奏，玩几轮就腻。逆转裁判类游戏的爽点在于：**有限 HP、必须找对证词、必须出示对证物**——我们想保留这套「压力 + 成就感」，让 LLM 负责「法官怎么回应、真宵怎么提示」，而不是替玩家直接通关。

**故事 / 观察 2：**  
独自推理时，玩家常卡在「我知道有问题，但说不清哪里矛盾」。真宵的角色设计正是为此：**她帮你分析证物、整理卷宗，但不直接泄露答案**——对应现实中「想讨论案件却找不到合适对象」的痛点，用 AI 助手补位。

---

### 3. 现有体验 / 方案还缺什么？

| 类型 | 不足 |
|------|------|
| **经典逆转裁判** | 流程固定、多周目重复；无「用自己的话辩护」的空间 |
| **通用 AI 聊天 RPG** | 缺少证物栏、证言记录、异议节奏等**结构化玩法** |
| **AI Agent 演示项目** | 多为对话 Demo，少有完整「调查 → 庭审 → 宣判」闭环 |
| **法庭题材独立游戏** | 多数仍依赖预设分支，难以动态评价玩家推理 |

**我们补位的方向：** 用 JSON 脚本保证案件骨架与节奏，用 LLM Agent（法官 / 检察官 / 真宵）负责**评价与对话**，在「可玩性」与「自由度」之间取平衡。

> **调研补充建议（可后续附上）：** 小范围问卷（是否玩过逆转系、能否接受 AI 法官）、5–8 人试玩访谈（卡关点、是否理解异议流程）、试玩留存与通关率数据。

## 三、做了什么（What）

### 核心设计功能（3 个）

---

#### 功能 1：LLM 驱动的庭审异议与犯罪现场还原

**功能名称：** 双阶段庭审引擎（脚本推进 + AI 评价）

**设计意图 / 解决的问题：**

- **Flow1（脚本）：** 开庭、检方举证、证人证言顺序固定，保证叙事节奏与新手引导。
- **Flow2（LLM）：** 玩家对矛盾证词提出「异议！」→ 选择证物并**用自己的话**说明矛盾 → AI 法官评判是否成立 → 通过后进入**犯罪现场还原**（分步输入推理）。
- 仅「有罪判决」扣 HP，选错证物/证词由真宵提示，降低挫败感，保留逆转裁判式「试错空间」。

**关键截图 / 流程：**

```
开庭致辞 → 检方出示证物 → 证人证言（交叉询问）
    ↓
选中矛盾证词 → [异议！] → 出示「现场照片」+ 文字说明
    ↓
法官 LLM 评判 → 犯罪现场还原（2 步关键词推理）
    ↓
异议成功特效 → 继续证言 → 结案陈词 → 无罪宣判
```

**建议配图：**

1. 庭审法庭背景 + 证人立绘 + 证言记录面板
2. 异议面板（证物选择 + 矛盾说明）
3. 异议成功弹出效果图（`material/picture/OIP-C.webp`）

**技术要点：** `TrialOrchestrator`、法官/检察官独立 Agent、分段 JSON 台词输出。

---

#### 功能 2：真宵 AI 助手与法庭记录（证物 + 案情卷宗）

**功能名称：** 真宵协作系统 & 法庭记录

**设计意图 / 解决的问题：**

- 推理游戏需要「场外大脑」：调查阶段分析证物、庭审阶段讨论证词、卡关时获取分级提示（HP 低时提示更直接）。
- **法庭记录** 统一入口：**证物栏**查看已收集证据；**案情梳理** 中玩家指导真宵维护卷宗（案件概要、时间线、证物摘要、矛盾疑点），对话与卷宗分离存储，避免与通用聊天混淆。
- 真宵按角色模板（性格、口吻、职责）生成回复，支持 `analyze_evidence`、`trial_hint`、`edit_dossier` 等多种意图。

**关键截图 / 流程：**

```
右上角 [法庭记录]
├── 证物：已收集证物网格 + 详情
└── 案情梳理：左侧与真宵对话 → 右侧卷宗实时更新

右上角 [真宵]：通用助手（分析证物 / 庭审提示 / 梳理时间线等）
```

**建议配图：**

1. 法庭记录 · 证物页
2. 案情梳理（对话 + 卷宗双栏）
3. 真宵聊天面板（分段气泡展示）

**技术要点：** 每会话独立 `mayaAgent`、`GameContextStore` 卷宗状态、`edit_dossier` 结构化 JSON 输出。

---

#### 功能 3：完整案件流程 MVP（《逆转的电梯》）

**功能名称：** 可编排案件 + 全链路玩法闭环

**设计意图 / 解决的问题：**

- 用一份可扩展的 `case01.json` 定义：前情、调查热点、必需证物、证人证言、可异议行、还原步骤、错误提示模板。
- 玩家完整路径：**标题选角 → 前情 → 庭前调查（3 场景）→ 庭审 → 宣判**，形成可演示、可通关、可复现的 MVP。
- 配套 BGM（标题/调查/庭审）、法庭背景、人物立绘、异议特效，保证「像一款游戏」而非纯 API Demo。

**关键截图 / 流程：**

```
[新游戏] 选成步堂
    → 前情提要（法庭背景 + 立绘对话）
    → 庭前调查：案发地 / 证人住所 / 事务所（收集凶器 + 现场照片）
    → [准备开庭]
    → 庭审（case01：电梯三楼 vs 证人一楼证词）
    → 无罪宣判
```

**建议配图：**

1. 标题页「成步堂的选择」
2. 调查场景 + 证物栏
3. 通关「无罪！」宣判页

**技术架构：** Monorepo（`web` + `server` + `shared` + `context-engine`），React 前端 + Hono 后端 + DeepSeek LLM，支持 Mock/联机双模式。

## 四、未来规划（如果晋级，下一步怎么做）

### 近 3 个月

- **内容：** 新增 1–2 个完整案件；扩展证人、多证人切换、Press（追问）与 Present 老机制整合。
- **AI：** 优化法官评判一致性；真宵卷宗支持「引用证物 ID」；减少 LLM 超时 fallback。
- **体验：** 存档/读档、更多立绘与场景图、移动端适配；小范围试玩 + 问卷（通关率、卡关步骤、AI 可信度评分）。
- **工程：** 案件编辑器（可视化编辑 JSON 证言/还原步骤）；CI 与基础 E2E 测试。

### 中长期（1 年内）

- **玩法：** 自定义案件 UGC 或模组；「真宵视角」完整可玩模式；联机观战或异步协助。
- **AI：** 多 Agent 编排（证人心理、检察官反驳链）；语音合成/识别接入庭审。
- **IP 边界：** 明确粉丝向 Demo 定位，探索原创角色与世界观，避免商用侵权风险。

### 商业化或落地设想（如适用）

| 方向 | 说明 |
|------|------|
| **教育 / 培训** | 法律逻辑、批判性思维、辩论练习的 gamified 沙盘 |
| **B 端定制** | 为企业/律所做「证据链梳理 + 模拟质证」训练工具 |
| **内容平台** | 案件 marketplace + AI 主持，创作者分成 |
| **C 端** | 买断制章节包或订阅「新案件 + AI 额度」；当前阶段以 MVP 验证留存与口碑为主 |
